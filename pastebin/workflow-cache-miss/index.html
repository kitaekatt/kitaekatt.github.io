Workflow cache-miss: parallel lanes don't share prompt cache

A reproduction kit for a Claude Code Workflow-tool inefficiency. Parallel sibling subagents ("lanes") each re-create the entire shared prompt prefix instead of reading it from cache — multiplying the shared-payload cost by ~N for an N-lane fan-out.

Filed upstream: anthropics/claude-code#63981

The finding

Anthropic's prompt cache is cross-request (keyed on prefix + org, ~5-min TTL), so identical prefixes across concurrently-firing lanes could share: the first lane creates the cache entry, the rest read it. They don't. Sibling lanes share only a small (~10k-token) fixed harness shell; everything beyond that — shared instructions in the user message and identical system-prompt content — is paid at the 1.25× cache_creation rate once per lane (vs the 0.1× cache_read rate it would cost if shared).

Probe A — shared prefix in the user message

A ~14k-token identical block at the front of each lane's agent() prompt, plus a pre-warm pass, then a 3-lane fan-out.

agentcache_createcache_read
prewarm~39.7k~8.7k
lane-0~38.7k~9.7k
lane-1~38.7k~9.7k
lane-2~38.7k~9.7k

The shared block is cache-created 4 times. Lanes read only the ~10k shell, never the shared prefix. Cause: agent() takes a single prompt string, so the shared head and the per-lane tail are one cache unit that differs per lane — no breakpoint can sit between them.

Probe B — shared content in the system prompt

Relies on the large fixed system prompt of a built-in agent type (the surface most likely to share). Pre-warm, then a 3-lane fan-out of the same type.

agentcache_createcache_read
prewarm~18.9k~8.7k
lane-0~17.6k~10k
lane-1~17.6k~10k
lane-2~17.6k~10k

Even the system prompt is re-created per sibling lane. Only the ~10k shell is shared.

Cross-lane "create-once" is not achievable in the Workflow tool today — neither user-message nor system-prompt content is shared across sibling lanes. Within a single lane, multi-turn caching works fine (cache_read dominates that lane's own turns); the gap is specifically cross-sibling.

Reproduce

  1. Launch a probe with the Workflow tool: Workflow({ scriptPath: ".../probe-a-prefix-sharing.js" }) (and the B probe). Each runs 1 pre-warm + 3 single-turn lanes.
  2. Find the transcripts at <session-project-dir>/subagents/workflows/<wf-id>/agent-*.jsonl (the launch result prints this path).
  3. Sum each agent's cache_creation_input_tokens vs cache_read_input_tokens:
import json, glob, sys
for f in sorted(glob.glob(sys.argv[1] + "/agent-*.jsonl")):
    ci = cr = 0
    for line in open(f, encoding="utf-8"):
        try: o = json.loads(line)
        except: continue
        m = o.get("message") if isinstance(o, dict) else None
        u = (m or {}).get("usage") if isinstance(m, dict) else None
        if isinstance(u, dict):
            ci += u.get("cache_creation_input_tokens", 0)
            cr += u.get("cache_read_input_tokens", 0)
    print(f, "cache_create=", ci, "cache_read=", cr)

Why it matters

cache_creation bills at 1.25× input, cache_read at 0.1×. With sharing, an N-lane fan-out over a shared prefix would pay ~1× create + (N−1)× read; without it, ~N× create. In a real multi-file audit workflow each lane re-created ~200–250k tokens, much of it identical shared criteria — an avoidable usage multiplier that grows linearly with lane count.
